# 富文本弹窗 + GrapesJS 联动方案

## 概述

Vue 弹窗富文本编辑器 + GrapesJS 画布双向通信。用户拖入或选中文本组件后，通过富文本弹窗编辑内容，确认后渲染到画布。

**核心设计原则：** 富文本弹窗完全独立，不感知 GrapesJS；所有 GrapesJS 交互逻辑集中在 page-builder 中管理。

---

## 富文本编辑器选型

**`<div contenteditable>` + 原生 `document.execCommand()`**

- 零外部依赖
- 支持常用富文本操作
- 输出标准 HTML，GrapesJS 直接渲染

> `execCommand` 已被 MDN 标记为 deprecated，但所有浏览器仍完整支持。如需未来兼容，可替换为 `document.getSelection()` + `Range API`，但当前阶段无实际影响。

## 核心数据流

### 场景一：新拖入

```
拖入 editable-text 块
     ↓
component:create → 判断 type === 'editable-text'
     ↓
存 activeComponent
读 getEl().innerHTML（此时是默认占位内容）
     ↓
打开弹窗，传入 initialContent
     ↓
┌──────────────────────────────────────────┐
│  rich-text-modal.vue                     │
│  - 用户编辑富文本                         │
│  - 点击确认 → emit('confirm', newHtml)   │
│  - 点击取消 → emit('cancel')             │
└──────────────────────────────────────────┘
     ↓
page-builder 收到 confirm(newHtml)
     ↓
写 DOM: activeComponent.getEl().innerHTML = newHtml
同步模型: activeComponent.set('content', '')  // 触发 update，保导出
     ↓
activeComponent = null → 关闭弹窗
```

### 场景二：编辑已有内容

```
选中已有 editable-text 组件
     ↓
Traits 面板显示 "编辑内容" 按钮
     ↓
点击按钮 → 执行 open-rich-text-modal 命令
     ↓
存 activeComponent
读 getEl().innerHTML（取画布当前最新内容）
     ↓
打开弹窗，传入 initialContent（回显已有内容）
     ↓  ...（同上面的弹窗编辑确认流程）
```

### 关键细节

**回显为什么用 `getEl().innerHTML`？**

- `component.get('content')` 只存初始 model 数据，DOM 手动修改后不同步
- `getEl()` 返回画布上真实 DOM 节点，`.innerHTML` 始终是最新
- 无论拖入新组件还是编辑已有组件，都能正确回显

**为什么写 DOM 后还要 `component.set('content', '')`？**

- 直接改 `innerHTML` 后 GrapesJS 的模型层可能不感知变化
- `getHtml()` / `getProjectData()` 导出时内容可能缺失
- 调用 `component.set('content', '')` 强制触发 `component:update` 事件，通知模型重新从 DOM 同步
- 此处 set 空字符串是让 GrapesJS 自己重新读取 DOM，而非传实际内容

**弹窗用 `v-if` 而非 `v-show`：**

- `v-if` 每次打开重建组件，保证 `initialContent` 干净写入，不受上次编辑残留影响
- `v-show` 会保留 DOM 状态，需要额外 watch 处理

## rich-text-modal.vue（纯展示组件）

### Props

| 属性 | 类型 | 说明 |
|------|------|------|
| `visible` | Boolean | 弹窗显隐（配合 `v-if` 使用） |
| `initialContent` | String | 初始 HTML 内容 |

### Emits

| 事件 | 参数 | 说明 |
|------|------|------|
| `confirm` | `(html: string)` | 用户确认编辑，返回清洗后的 HTML |
| `cancel` | - | 用户取消编辑 |

### 内部实现

- 挂载时调用 `document.execCommand('styleWithCSS', false, true)` 确保颜色生成 `<span style>` 而非 `<font>`
- 工具栏按钮调用 `document.execCommand(cmd)` 操作选区
- 编辑区为 `<div ref="editorEl" contenteditable>`，`v-html` 渲染初始内容
- 确认时读取 `editorEl.value.innerHTML`，做清洗后返回
- **完全不知晓 GrapesJS 存在**

### HTML 清洗策略（确认时执行）

```
1. 移除空标签: <p></p> → 删除
2. 移除空 span: <span style=""></span> → 删除
3. 合并连续 <br>: <br><br><br> → <br>
4. 修剪首尾空白文本
```

## page-builder.vue（调度层）

### 1. 注册自定义组件 `editable-text`

```js
editor.DomComponents.addType('editable-text', {
  model: {
    defaults: {
      name: '富文本',
      draggable: true,
      traits: [
        {
          type: 'button',
          name: 'edit-content',
          label: '编辑内容',
          text: '打开富文本编辑器',
          command: 'open-rich-text-modal',
        },
      ],
    },
  },
})
```

### 2. 注册命令

```js
editor.Commands.add('open-rich-text-modal', {
  run(editor, sender) {
    const component = editor.getSelected()
    if (!component || activeComponent) return  // 防重复
    activeComponent = component
    showRichTextModal.value = true
  },
})
```

### 3. 拖入时自动弹窗

在 `component:create` 中判断：

```js
editor.on('component:create', (component) => {
  if (component.get('type') === 'editable-text') {
    activeComponent = component
    showRichTextModal.value = true
  }
})
```

### 4. 弹窗回调处理

```js
function onRichTextConfirm(html) {
  if (!activeComponent) return
  activeComponent.getEl().innerHTML = html
  activeComponent.set('content', '')  // 通知模型，保导出
  activeComponent = null
  showRichTextModal.value = false
}

function onRichTextCancel() {
  activeComponent = null
  showRichTextModal.value = false
}
```

### 5. 注册 block

```js
{
  id: 'comp-editable-text',
  label: '富文本块',
  category: '文本组件',
  content: `<div data-gjs-type="editable-text" style="padding:16px;min-height:48px;">
    <p style="margin:0;color:#999;">点击编辑内容</p>
  </div>`,
}
```

## 实现步骤

1. 新建 `rich-text-modal.vue` — 工具栏 + contenteditable + 弹窗 + HTML 清洗
2. `page-builder.vue` — 引入弹窗，添加 `showRichTextModal` / `activeComponent` 状态
3. 注册 `editable-text` 组件类型（含 button trait）
4. 注册命令 `open-rich-text-modal`
5. `component:create` 中监听 `editable-text` 自动弹窗
6. `text-components.js` 添加 `comp-editable-text` block
7. 确认 `registerCustomBlocks` 的 keys 包含 `textComponents`

## 注意事项

| 问题 | 解决 |
|------|------|
| **焦点冲突** | 弹窗用 Element Plus `<el-dialog>`，modal 模式自动阻断 GrapesJS 键盘捕获 |
| **HTML 脏标签** | 确认前清洗（移除空标签、合并 `<br>`） |
| **activeComponent 泄漏** | confirm / cancel / dialog close 后必须置空；命令入口防重复 |
| **模型不同步** | 确认时调用 `component.set('content', html)` 同步模型和 DOM，保证导出正确 |
| **新组件占位内容** | 拖入时弹窗打开传入占位 HTML，用户确认后替换；取消则保留占位 |
